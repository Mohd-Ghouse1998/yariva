## Status rules

- `[x]` = completed with evidence for that task's acceptance criteria.
- `[ ]` = incomplete. Add `IN PROGRESS`, `BLOCKED — reason`, or `NEEDS RECHECK — reason` after the task when appropriate; keep its box unticked.
- Feature completion requires all its applicable implementation, integration, testing and device criteria below. A migration, mockup or successful build alone does not complete a feature.
- Record evidence against task IDs. A code task and its device-test task can have different completion states.
- Update checkboxes, evidence and this checkpoint after each meaningful task completes, and before a handoff/final response. Keep changes small; do not copy the full tracker into chat.
- Reopen only affected tasks if a regression or changed dependency invalidates their evidence. Keep the reason and prior evidence traceable.
- Planning ticks are separate from feature progress. Out-of-scope work is not silently counted as done; record any agreed scope change explicitly.
